Methodology and privacy

Benchpress answers buying questions with real builds: clean builds, incremental rebuilds and cargo check on pinned Rust projects, measured on the machines people actually use.

What a run does

  • Installs the suite's exact Rust toolchain into Benchpress's own cache with rustup-init, verified by checksum. Your ~/.rustup and ~/.cargo are never touched.
  • Downloads the project at a pinned commit, verifies the archive's SHA-256 and extracts it outside your home directory, on disk (/var/tmp on Linux, $TMPDIR on macOS; never a RAM-backed /tmp).
  • Fetches dependencies once, untimed. Every measured command then runs with --offline, so the network never affects a result.
  • Runs every command from an empty environment plus a short allowlist. RUSTC_WRAPPER (sccache), RUSTFLAGS, custom linkers and other shell settings are ignored, and the run refuses to start if any cargo config file sits above the build directory.
  • Clean scenarios delete the target directory before each run. Incremental scenarios append a comment to one source file before each run and restore it afterwards.
  • Rests between runs (10 seconds by default) and records thermal state where the OS reports it.

What is measured

  • Wall time from spawning cargo to its exit. Each scenario runs three times; results show the median.
  • CPU time of cargo and every rustc it starts, from the kernel's child resource usage.
  • Memory: system memory and swap sampled every 250 ms, reported as the peak above the level before the run. On Linux, memory pressure (PSI) too.
  • Variation: the coefficient of variation across runs. Above 10% the result is flagged.

macOS scans new executables such as build scripts and proc-macros, which slows Rust builds. Adding your terminal under System Settings → Privacy & Security → Developer Tools avoids it. Benchpress cannot read that setting without privileges, so it records it as unknown.

Privacy

Nothing leaves your machine unless you publish. Before upload, Benchpress shows the exact JSON and asks you to confirm. Published results are public.

  • Collected: CPU model and core counts, RAM size, disk type and model, machine model name, OS version and kernel, power source, thermal state, the timings above, and the names (never values) of build variables found in your shell.
  • Never collected: hostname, username, home directory or any absolute path, serial numbers, hardware UUIDs, MAC or IP addresses.
  • The server never stores IP addresses and keeps them out of its logs. Rate limiting happens in memory only.
  • Each upload returns a delete token saved on your machine; benchpress unpublish <id> removes the result.

Trust

Results are not signed. Trust comes from validation and aggregation: the server checks suite hashes, run counts and plausibility (CPU time within what the cores can provide, memory within RAM plus swap, build times above a per-suite floor), rejects exact duplicates, and shows medians over many machines.
